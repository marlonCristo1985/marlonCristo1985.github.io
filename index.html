Gate sem código de barras e reescrito em mensageria

A barcode-free gate, rebuilt on messaging

O gate decide em segundos se um caminhão entra ou sai do terminal. Testei as duas mudanças mais profundas desse sistema: tirar o código de barras do processo e migrar para o novo SGG, reescrito em mensageria.

The gate decides in seconds whether a truck may enter or leave the terminal. I tested the two deepest changes that system went through: taking the barcode out of the process and moving to the new gate system (SGG), rebuilt on messaging.

Por que é críticoWhy it's critical

Em cada passagem o gate cruza OCR de placas e contêineres, balança, biometria do motorista, inspeção prévia, agendamento, o sistema operacional do terminal (TOS) e o armazém. Se uma regra falha, o caminhão para na cancela e a fila chega à rodovia.

On every pass the gate combines plate and container OCR, a weighbridge, driver biometrics, the pre-gate inspection, the appointment, the terminal operating system (TOS) and the warehouse. If one rule fails, the truck stops at the barrier and the queue backs up onto the highway.

Parte 1 · Tirar o código de barras sem perder o controlePart 1 · Removing the barcode without losing control

Antes, o motorista apresentava uma guia com código de barras para o gate identificar o agendamento. Com a mudança, o sistema passou a descobrir o agendamento pela placa lida no OCR, buscando no histórico de inspeção da última hora ou no período de atraso configurado. Eu desenhei o novo processo em raias, com os sete atores, antes de escrever qualquer teste.

Previously the driver presented a slip with a barcode so the gate could identify the appointment. After the change, the system finds the appointment from the OCR-read plate, searching the inspection history for the past hour or the configured delay window.   • The error path, end to end: the "no appointment found for this plate or truck not inspected" message reaches the operator, the analyst corrects the data, the automation builds a new message, and the flow restarts.

Parte 2 · O novo SGG em mensageriaPart 2 · The new gate system (SGG) on messaging

AntesBefore

O sistema do gate chamava o TOS e o armazém diretamente e esperava as respostas para decidir.

The gate system called the TOS and the warehouse directly and waited for their replies to decide.

DepoisAfter

O gate publica um evento, cada sistema consome o evento de forma independente e devolve sucesso ou falha em outro evento. A falha de um sistema vira um evento rastreável, em vez de um travamento.

The gate publishes an event, each system consumes it independently and returns success or failure as another event. A failure in one system becomes a traceable event instead of a hang.

O resultado esperado de cada linha é liberar, bloquear com erro ou gerar o documento de entrada. Com a matriz em mãos, fiz a validação estática dos requisitos antes do desenvolvimento.

To make sure no access combination was left out of the new SGG, I crossed 5 input variables in a decision table (cargo type, entry or exit, inspection status, vehicle already in the yard, vehicle type) and multiplied by the 19 appointment types. The expected result of each row is allow, block with an error, or issue the entry document. With the matrix in hand, I ran a static review of the requirements before development.

Um checklist de 11 pontos para migrar views sem quebrar quem as consome

An 11-point checklist for migrating views without breaking their consumers

Antes da troca do TOS, as views que alimentavam telas, APIs e painéis foram reescritas para uma camada intermediária. Eu criei o método para provar, com SQL e evidência, que nada mudou para quem usa esses dados.

Ahead of the TOS switch, the views feeding screens, APIs and dashboards were rewritten onto an intermediate layer. I built the method to prove, with SQL and evidence, that nothing changed for anyone using that data.

O riscoThe risk

Uma view pode compilar, devolver linhas e passar num teste superficial, mas com uma coluna que mudou de significado. Nesse caso nada dá erro: a tela continua funcionando e mostra o dado errado. E cada view tinha consumidores diferentes, cada um com um jeito de quebrar.

A view can compile, return rows and pass a shallow test while one column has quietly changed meaning. Nothing errors out: the screen keeps working and shows the wrong data. And each view had different consumers, each of which could break in its own way.

1. Checklist de testes: 11 verificações, cada uma com evidência1. Test checklist: 11 checks, each with evidence

  1. ESTO código da view nova não referencia o schema do TOS antigo.The new view's code has no references to the old TOS schema.
  2. ESTTermos próprios do TOS antigo (chaves internas, por exemplo) não sobrevivem no script nem nos nomes de coluna.Old-TOS-specific terms (internal keys, for instance) don't survive in the script or in column names.
  3. ESTQuantidade e nomes das colunas iguais aos da view antiga.Same number and names of columns as the old view.
  4. ESTTipos de dados e tamanhos das colunas iguais.Same column data types and sizes.
  5. DADOMesma semântica: comparar o retorno da view antiga com o da nova. Se a coluna retornava o número do contêiner, ela ainda precisa retornar o número do contêiner.Same meaning: compare the old view's output with the new one's. If a column returned the container number, it must still return the container number.
  6. DADOQuestionar todo retorno nulo nas colunas.Challenge every null returned in any column.
  7. PERFTempo de resposta da view nova medido em QA e em produção.New view's response time measured in QA and in production.
  8. DEPViews auxiliares do mesmo processo identificadas, com a decisão de migrar ou não.Auxiliary views in the same process identified, with a decision on whether to migrate them.
  9. DADOContagem de registros com os mesmos filtros que a tela aplica, não com um SELECT * solto.Record counts using the same filters the screen applies, not a bare SELECT *.
  10. CENCenários criados a partir dos filtros da própria view (condições do WHERE e dos subselects).Scenarios derived from the view's own filters (WHERE conditions and subselects).
  11. CENCenários criados a partir da tela mapeada na documentação de usuário e na técnica.Scenarios derived from the screen as mapped in the user and technical documentation.
